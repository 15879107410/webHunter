# Repository Instructions

## Execution Style

- Follow the development order defined in `DEV-plan.md`.
- Continue working autonomously through the next tasks without stopping after a single completed item.
- Do not wait for user confirmation between normal development steps.
- If a step requires a product or business decision from the user, skip that blocking step for now, continue with the next non-blocking task, and report the pending decision later when the user checks in.
- Proactively run development, testing, debugging, and verification commands as needed.
- Keep advancing the project until all feasible tasks in the current development sequence are completed.

## Priorities

1. Frontend implementation with real routes and mock data
2. Shared types and API contracts
3. Backend skeleton and basic CRUD
4. Real analysis pipeline integration

## Progress Reporting

- When the user returns and asks for status, summarize completed work first.
- Then list any blocked decisions that still require user input.
- If there are no blockers, continue implementing the next tasks in sequence.
